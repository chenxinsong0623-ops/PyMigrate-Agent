# 六周项目开发资料索引

日期：2026-07-30

## 先看结论

最终保留两个项目：

1. **MigrationLens**：Pydantic v1→v2 升级影响分析 Agent。
2. **WDI-ClaimCheck**：World Bank 发展指标事实核查 Agent。

开发顺序必须是 MigrationLens 在前、WDI-ClaimCheck 在后。不要同时开工，也不要再加入第三个项目。

## 第一天实际动作

1. 新建 `migration-lens` 仓库。
2. 把 MigrationLens 规格书复制为仓库的 `SPEC.md`。
3. 从 Codex 提示词文件复制 `AGENTS.md`。
4. 在 `TASKS.md` 中只放 M01。
5. 冻结实际 LLM 名称；若尚未决定，先用 FakeLLM 完成 M01。
6. 用提示词文件最后一节的 MigrationLens 首条消息启动 Codex。
7. 当天只验收脚手架、health、模型接口、SQLite 和 Docker 配置，不提前写 Agent。

## 每周是否继续的判断

- 第 1 周末：文档快照、12 个 dev fixtures 和容器底座均存在，才进入扫描器开发。
- 第 2 周末：8 类规则能稳定定位文件和行号，才接 Agent 报告。
- 第 3 周末：MigrationLens 有 v1.0、评测和失败分析，才把主要时间转到 WDI。
- 第 4 周末：WDI 固定 Parquet、预建只读 DuckDB 与五个确定性工具均可离线运行，才接 LLM。
- 第 5 周末：27 道 locked 题完成独立复算和人工复核后，才运行一次最终对比。
- 第 6 周：只做复现、评测、README、演示、简历和面试，不再加入新功能。

## 最低可交付版本

如果进度落后，按以下顺序缩减：

1. 删除两个项目的网页界面。
2. 删除 Redis/RQ、Prometheus 和本地模型 profile。
3. WDI 停留在 P0 的 8 个指标、35 题；不做 12 指标/55 题 P1。
4. 如果 pgvector 成为阻塞，通过 `DECISIONS.md` 和新版 SPEC 正式切换为 BM25 +本地 dense index；readiness、README 和简历同步改为真实架构。
5. MigrationLens 保留 40 个 fixture 与 32 条检索题，不在锁定后临时缩分母。
6. 保留 FastAPI、有限状态 Agent、RAG、确定性工具、Docker、测试和真实评测。

任何缩范围或换 backend 都必须先更新 `DECISIONS.md`、SPEC 版本和验收条件，不能只改代码。

不能缩减：

- 数据来源和 SHA256。
- WDI `source_id=2`、逐指标许可/归属门禁；无再分发权时只发布构建脚本。
- dev/locked 隔离。
- 独立 reference evaluator；不得让被测工具给自己生成 gold。
- locked 冻结后不得用于调 prompt、规则、工具或 Verifier。
- 输入安全和受控工具。
- 失败/拒答路径。
- 实际测试报告。
- 简历数字可追溯性。

## 简历原则

规格书里的 fixture 数、题目数、准确率、召回率、延迟和并发都是**计划或候选验收项**。只有仓库报告实际生成后，才能写成完成结果。

最终项目 bullet 应来自：

- `reports/eval.json`
- `reports/loadtest.json`
- `reports/failures.md`
- 数据 manifest
- GitHub tag/commit

当前旧简历采用大量文本框，最后一周应重建为正文段落和标准标题的一页 ATS 友好版，而不是继续在原文本框模板上堆内容。
